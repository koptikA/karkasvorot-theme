## Что должно заработать

На любой странице посетитель оставляет заявку: имя, телефон, изделие, комментарий, галочка согласия. Ошибки — по-русски у поля, введённое сохраняется. Заявка пишется в «Заявки» в админке, потом уходит письмом на e-mail из настроек, посетитель видит «Спасибо». Обновление страницы не дублирует. Боты отсекаются. Cookie-баннер: «Принять» включает Метрику, «Отклонить» — нет; выбор запоминается; цели срабатывают.

## Состав

- `kv_order_form(['product'=>…])`: `<form id="zayavka" method="post" action="…/wp-admin/admin-post.php">`, `action=kv_order`; поля: имя (необяз.), телефон (обяз., `type="tel"`, `autocomplete="tel"`), изделие (select: Каркас откатных ворот / Каркас распашных ворот / Калитка / Каркас мебели / Обувница / Забор / Навес или беседка / Другое), комментарий, чекбокс «Согласен на обработку персональных данных» со ссылкой на `/politika-konfidencialnosti/` (обяз.), скрытые `kv_hp` (ловушка), `kv_ts` (время рендера), `kv_back` (URL возврата), `kv_req` (случайный id запроса). `<label>` у всех полей, ошибки связаны `aria-describedby`, `role="alert"` у сводки.
- Обработчик: ловушка заполнена или < 3 с → тихий «успех» без сохранения; телефон нормализуется к `+375XXXXXXXXX` (принимать `80…`, `375…`, `+375…`, пробелы/скобки/дефисы; иначе «Укажите телефон в формате +375 XX XXX-XX-XX»); нет согласия → ошибка; ошибки → редирект назад с `zayavka=err&kv_req=…`, введённые значения и коды ошибок — в transient на 10 мин по `kv_req` (не в URL); успех → `wp_insert_post` типа `lead` (заголовок «Заявка: <телефон>», мета: имя, телефон, изделие, комментарий, страница, время; IP не храним) **до** `wp_mail`; повтор того же `kv_req` → вторая не создаётся; письмо на `kv_opt('lead_email')` или `admin_email`; редирект `?zayavka=ok#zayavka`. Валидировать `kv_back` через `wp_validate_redirect`.
- Админка: колонки «Телефон», «Изделие», «Дата» в списке заявок.
- «Спасибо! Мы перезвоним в ближайшее время.» при `zayavka=ok`; JS шлёт цель `form_submit` при этом сообщении.
- `assets/site.js`: cookie-баннер (`template-parts/cookie-banner.php` в `wp_footer`, текст со ссылкой на политику), `localStorage kv_consent` в try/catch, загрузка стандартного тега Метрики (ID из `data-metrika`) только при `yes` и непустом ID; клики по `[data-goal]` → `ym(id,'reachGoal',goal)`, если `ym` есть.
- `tools/checks/leads.py`: форма на главной и услугах (если страниц ещё нет — на главной); POST без телефона → ошибка и сохранённое имя; без согласия → ошибка; валидный POST (старый `kv_ts`) → `zayavka=ok` и заявка появилась (проверка через PHP/WP-код на стенде — способ в `tools/README.md`); тот же `kv_req` повторно → заявок не прибавилось; ловушка → не прибавилось; `/?post_type=lead` и `/wp-json/wp/v2/lead` гостю недоступны; баннер в HTML; в HTML нет `mc.yandex.ru` (Метрика только через JS после согласия).

## Критерии приёмки

- [ ] Все сценарии `leads.py` зелёные
- [ ] Заявка сохраняется, даже если `wp_mail` вернул false
- [ ] Метрика не грузится без «Принять»; цели вызываются только при загруженной Метрике
- [ ] Доступность формы: подписи, фокус, ошибки читаются скринридером
